# طرح مهاجرت احراز هویت و نقش‌ها

وضعیت: **فقط طرح**. در این محیط هیچ ورود واقعی، رمز، توکن یا هویت بیرونی فعال نیست و هیچ دادهٔ کاربر واقعی لمس نمی‌شود.

منبع داده‌ای: `src/core/transfer/authMigration.js`.

## نگاشت نقش‌ها

| نقش محلی | سطح | نقش مقصد | توضیح |
|---|---|---|---|
| creator | ۱۰۰ | مالک فضای کاری | دسترسی کامل؛ مدیریت کاربران و تنظیمات سطح بالا |
| admin | ۸۰ | نقش admin پلتفرم | مدیر صرافی؛ دسترسی کامل به داده و کاربران |
| sarraaf | ۵۰ | user + فیلد `sarraaf_level = owner` | نقش پلتفرم تغییر نمی‌کند؛ تخصص در فیلد جدا |
| employee | ۳۰ | user + فیلد `sarraaf_level = staff` | دسترسی از جدول مجوز کارمند می‌آید |
| customer | ۱۰ | user + فیلد `sarraaf_level = customer` | فقط پوستهٔ مشتری |

قاعدهٔ مهم: مقدار `role` پلتفرم دست‌کاری نمی‌شود؛ نقش تخصصی صرافی در فیلد جداگانه نگه داشته می‌شود تا قواعد دسترسی پلتفرم دست‌نخورده بماند.

## نقاط اجرای مجوز (امروز فعال، مبتنی بر قاعدهٔ مشترک)

۱. گیت پوسته (`A1Guard`): مسیرهای پنل صراف و پنل مشتری بر پایهٔ نقش بسته می‌شوند.
۲. مجوز بخش (`checkPermission`): نمایش بخش و دکمه‌های ثبت/ویرایش/حذف را تعیین می‌کند؛ نبود مجوز یعنی بسته.
۳. سلسله‌مراتب نقش (`canManageRole`): مدیریت نقش پایین‌تر مجاز و مدیریت نقش بالاتر رد می‌شود.
۴. نشست: امروز نمایشی و محلی است؛ در نسخهٔ واقعی جای خود را به نشست پلتفرم می‌دهد.

## تصمیم‌های باز پیش از اتصال

| تصمیم | گزینه‌ها | اثر |
|---|---|---|
| دامنهٔ دادهٔ صرافی | `exchange_code` روی رکوردها / فضای کاری جدا برای هر صرافی | بدون این تصمیم، کاربر یک صرافی می‌تواند دادهٔ صرافی دیگر را ببیند |
| محل مجوز کارمند | جدول مجوز اختصاصی / فیلد روی کاربر | شکل ذخیره، قاعدهٔ RLS و صفحهٔ کاربران را تعیین می‌کند |
| منبع نشست | ورود پلتفرم / ورود سازمانی (SSO) | بازیابی رمز، دعوت و بازبینی نشست به آن وابسته است |
| سیاست افزودن کارمند | دعوت مدیر صرافی / درخواست و تأیید | دعوت، ایمیل پلتفرم و فهرست کاربران را درگیر می‌کند |

## گام‌های اجرا در نسخهٔ اصلی

۱. تصمیم‌های بالا ثبت شود.
۲. نقش تخصصی به فیلد کاربر اضافه و مقدارش فقط توسط مدیر قابل تغییر باشد.
۳. قاعدهٔ دسترسی رکوردها (RLS) با دامنهٔ صرافی نوشته شود.
۴. نشست نمایشی حذف و گیت‌ها روی نشست پلتفرم سوار شوند.
۵. آزمون دسترسی: هر نقش فقط بخش‌های مجاز را ببیند و صرافی دیگر را نبیند.
