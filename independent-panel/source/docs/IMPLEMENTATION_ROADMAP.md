## مرحله ۱ — امنیت و چندصرافی (اولویت بحرانی)

وابستگی: هیچ. بدون این مرحله هیچ استفادهٔ واقعی مجاز نیست.

1. فعال‌کردن ورود Base44 برای پنل صراف و پنل مشتری؛ نگاشت نقش‌ها به `User.role`.
2. افزودن `exchange_code` به همهٔ نوشتن‌ها و فیلتر همهٔ خواندن‌ها.
3. نوشتن RLS بر اساس `created_by_id`/`exchange_id` (پیشنهاد در COMPATIBILITY_REPORT، اجرا نشده).
4. معیار پذیرش: کاربر نقش `customer` نتواند هیچ رکورد عملیاتی صراف را بخواند؛ تست با دو کاربر.

## مرحله ۲ — انطباق موتور ثبت با A1 (اولویت بالا)

وابستگی: مرحله ۱ برای داده واقعی، اما توسعهٔ موازی ممکن است.

1. پذیرش انواع سند A1: `buy, sell, dadogereft, internal_transfer, transfer_send, transfer_receive,
   transfer_execute, convert, open_balance, manual`.
2. ثبت موازی `Conversion`, `BankTransaction`, `TreasuryTransaction`, `JournalEntry` مطابق تصمیم نهایی.
3. افزودن `client_operation_id` + جدول `IdempotencyKey` به مسیر ثبت.
4. پیاده‌سازی `transfer_execute` به‌عنوان سند، هنگام تغییر وضعیت حواله به `done`.
5. محاسبهٔ سود مطابق `computeProfitDetailed` (کارمزد + اختلاف نرخ `rates.daily_rate`).
6. تراز/ارزش‌گذاری با `app_settings.usd_afn` و `afn_toman`.
7. معیار پذیرش: اسناد نمونهٔ A1 بازسازی و توازن هر سند و تراز کل صفر شود؛ دو ثبت با یک
   `client_operation_id` فقط یک سند بسازد.
