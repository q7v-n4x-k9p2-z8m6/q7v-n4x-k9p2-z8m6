# معماری هستهٔ حساب صراف (قابل انتقال به نسخهٔ واقعی)

این سند نقشهٔ وابستگی‌ها، مرزهای لایه‌ها و مسیر اتصال آینده به نسخهٔ واقعی است. قاعدهٔ اصلی: **رابط کاربری، منطق کسب‌وکار و دسترسی به داده سه لایهٔ جدا هستند** و هیچ‌کدام فیلد یا قاعدهٔ دیگری را حذف نمی‌کند.

## لایه‌ها و جهت وابستگی

```
src/core/**            ← دامنه و قراردادها (بدون React، بدون Base44، بدون مرورگر)
src/adapters/**        ← پیاده‌سازی درگاه روی یک منبع دادهٔ مشخص
src/demo/**            ← دادهٔ آزمایشی (فقط حافظه)
src/app/container.js   ← ریشهٔ ترکیب: انتخاب پیاده‌سازی درگاه
src/a1/**, src/pages/**← رابط کاربری (لپ‌تاپ، موبایل، پنل مشتری)
```

- `core` به هیچ لایهٔ دیگری وابسته نیست (فقط importهای نسبی داخلی خودش).
- `adapters` می‌تواند به `core` و به موتور دادهٔ موجود (`src/a1/lib`) وابسته باشد.
- رابط کاربری فقط از `src/app/container.js` درگاه می‌گیرد، نه از موتور داده.
- هیچ‌جای `core` از Base44، Supabase یا IndexedDB خبری نیست.

## قرارداد درگاه داده

`src/core/gateway/contract.js`

| عملیات | کارکرد |
|---|---|
| `snapshot()` | وضعیت جاری برای رندر React |
| `subscribe(listener)` | اطلاع از تغییر، خروجی تابع لغو اشتراک |
| `list(collection, query)` / `get` / `count` | خواندن با جستجو، ارز، بازهٔ تاریخ و فیلتر برابری |
| `create` / `update` | ایجاد و ویرایش رکورد |
| `deactivate` | غیرفعال‌سازی بدون حذف فیزیکی (حفظ سابقه و روابط) |
| `remove` | حذف رکورد |
| `replaceAll` | جایگزینی کامل یک مجموعه (تنظیمات، گفت‌وگو) |
| `clearExcept` / `reset` | پاک‌سازی نمایشی و بازگردانی دادهٔ اولیه |

`GatewayError` با کدهای `NOT_FOUND`، `NO_GATEWAY` و `INVALID_GATEWAY` تنها شکل خطای قرارداد است. آزمون‌های قرارداد در `src/core/gateway/contractTests.js` هستند و در حالت توسعه به‌طور خودکار روی درگاه حافظه‌ای اجرا می‌شوند؛ هر پیاده‌سازی جدید هم باید از همان‌ها بگذرد.

## پیاده‌سازی‌های امروز

- `src/core/gateway/memoryGateway.js` — درگاه حافظه‌ای دمو؛ هیچ ذخیره‌سازی پایدار ندارد. با بارگذاری مجدد صفحه به دادهٔ اولیه برمی‌گردد.
- `src/adapters/a1/laptopEngineGateway.js` — آداپتر لپ‌تاپ با قرارداد کامل درگاه (۱۳ عملیات) روی همان موتور نسخهٔ ۲۱؛ پل پیش‌فرض همین `a1EngineGateway` است و برای آزمون می‌توان پل حافظه‌ای داد.
- `src/adapters/a1/a1EngineGateway.js` — آداپتر میزکار لپ‌تاپ روی موتور محلی نسخهٔ ۲۱ (IndexedDB). تمام عملیات مالی، scoping صرافی (`exchange_code`)، ابطال سند و سوابق در همان موتور باقی مانده است.

## رجیستری مرکزی (یک منبع برای فیلدها)

- `src/core/registry/schemas.js` — تنها تعریف فیلدهای فرم‌ها؛ هم میزکار لپ‌تاپ و هم فرم‌های موبایل از همین‌جا می‌خوانند. هیچ فیلدی در موبایل تکرار یا حذف نشده است.
- `src/core/registry/masterForms.js` — فرم‌های تعریف، ساخته‌شده از همان جدول.
- `src/core/registry/modules.js` — ۲۵ بخش، گروه‌ها، بخش‌های «فقط بیشتر»، بخش مجوز و مجموعه‌دادهٔ هر بخش (بدون آیکون و بدون JSX).

## دامنه (قواعد مشترک)

- `src/core/domain/posting.js` — ساخت پیش‌نویس، اعتبارسنجی و نرمال‌سازی فرم‌های مالی (مصرف، حواله، اسعار، روزنامچه، گردش صندوق) + نگاشت مجموعهٔ ذخیره‌سازی.
- `src/core/domain/balances.js` — موجودی صندوق و مانده طرف حساب.
- `src/core/domain/access.js` — قاعدهٔ مجوز و سلسله‌مراتب نقش (لایهٔ احراز هویت مستقل و قابل تعویض است).
- `src/core/domain/currencies.js` و `dates.js` — برچسب ارز و تاریخ کاری.

پوسته‌های سازگاری `src/a1/lib/permissions.js`، `src/a1/lib/format.js` و `src/a1/mobile/demoData.js` فقط نام‌های قبلی را نگه می‌دارند و منطق تکراری ندارند.

## اتصال نسخهٔ واقعی

1. یک آداپتر جدید در `src/adapters/<backend>/` بسازید که همان امضای `a1EngineGateway` یا همان قرارداد کامل درگاه را پیاده کند.
2. آن را در `src/app/container.js` جایگزین کنید (مثلاً برای موبایل به‌جای `getDemoGateway`).
3. هیچ صفحه، فرم یا قاعدهٔ دامنه‌ای تغییر نمی‌کند؛ فیلدها و اعتبارسنجی‌ها همان‌اند.

## وضعیت مهاجرت و استثناها

| بخش | وضعیت |
|---|---|
| فیلدهای فرم‌ها (لپ‌تاپ و موبایل) | یک منبع مشترک در `core/registry/schemas.js` |
| قواعد فرم مالی موبایل | منتقل‌شده به `core/domain/posting.js` |
| دادهٔ دموی موبایل | از طریق درگاه حافظه‌ای، بدون ذخیره‌سازی |
| ناوبری و آیکون‌های موبایل | روی رجیستری مرکزی، آیکون‌ها در لایهٔ نمایش |
| میزکار لپ‌تاپ | از طریق آداپتر به موتور محلی وصل است؛ منطق مالی موتور دست‌نخورده |
| منطق مالی لپ‌تاپ (`v21Write`, `v21Data`, `v21Rules`) | عمداً دست‌نخورده؛ انتقال آن باید با آزمون‌های دامنه و در گام بعدی انجام شود |
| احراز هویت | `demoAuth` و مسیر ورود پلتفرم؛ خارج از دامنه، قابل تعویض |
| مجوزهای کارمند | قاعدهٔ مشترک در `core/domain/access.js`، دادهٔ نمایشی در `src/demo/seed.js` |

استثنای مستند: موتور نوشتن (`src/a1/lib/v21Write.js`) همچنان مستقیماً با IndexedDB کار می‌کند و آداپتر لپ‌تاپ از طریق پل به آن وصل است؛ قرارداد کامل درگاه در لایهٔ آداپتر پیاده و آزمون شده است تا رفتار مالی و ابطال تغییر نکند.
