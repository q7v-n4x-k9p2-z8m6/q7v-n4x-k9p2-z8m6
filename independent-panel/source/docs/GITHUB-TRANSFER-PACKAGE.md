## ۳. گام‌به‌گام انتقال

مخزن محلی از قبل Git دارد (شاخهٔ `main`) و `origin` فعلی، میزبان Base44 است.
برای رفتن به GitHub، `origin` را تغییر نام دهید تا تاریخچه حفظ شود:

```bash
# ۱) نگه‌داشتن مبدأ فعلی زیر نام base44
git remote rename origin base44

# ۲) افزودن مخزن خالی GitHub (پیش از این، در GitHub یک ریپوی خالی بسازید)
git remote add origin https://github.com/<user>/<repo>.git

# ۳) بررسی اینکه چیزی از فایل‌های ممنوع وارد نشود
git status --porcelain          # باید خالی یا فقط تغییرات مستندات باشد
git check-ignore -v node_modules dist .env base44/.app.jsonc

# ۴) فرستادن شاخه
git branch -M main
git push -u origin main
```

نکته‌ها:

- اگر نمی‌خواهید تاریخچه منتقل شود: `git init` در پوشهٔ تازه و کپی فایل‌ها، سپس push.
- بزرگ‌ترین ریسک انتقال، فراموش‌کردن `reference/` است؛ خروجی `git ls-files reference | wc -l` باید ۸۳۷ باشد.
- `backups/` خالی است و در Git فایلی از آن ثبت نمی‌شود؛ ایجاد دستی آن لازم نیست.

## ۵. متغیرهای محیطی

فایل `.env` در مخزن نیست (در `.gitignore` است). برنامه فقط سه متغیر می‌خواند، همه در
`src/lib/app-params.js`، و همه با پیشوند `VITE_`:

| متغیر | مصرف | اگر نباشد |
| --- | --- | --- |
| `VITE_BASE44_APP_ID` | شناسهٔ اپ در کلاینت `src/api/base44Client.js` | کلاینت بدون شناسه ساخته می‌شود؛ درخت اصلی برنامه همچنان اجرا می‌شود |
| `VITE_BASE44_FUNCTIONS_VERSION` | نسخهٔ توابع پلتفرم | خالی می‌ماند؛ برنامه توابع backend ندارد |
| `VITE_BASE44_APP_BASE_URL` | آدرس پایهٔ سرویس | خالی می‌ماند |

اگر برنامه را کامل مستقل می‌کنید، این سه متغیر لازم نیستند؛ در عوض باید سه نقطهٔ وابستگی بخش ۷ برداشته شوند.
برای CI، نمونهٔ امن:

```bash
# .env.example (بدون مقدار واقعی)
VITE_BASE44_APP_ID=
VITE_BASE44_FUNCTIONS_VERSION=
VITE_BASE44_APP_BASE_URL=
```

## ۶. چک‌لیست پذیرش انتقال

پس از push و کلون تازه، این ده مورد را بررسی کنید:

1. `git ls-files | wc -l` عددی نزدیک به مجموع فایل‌های بسته را می‌دهد و `reference/` در آن هست.
2. `git ls-files node_modules` خروجی خالی دارد.
3. `npm install` بدون خطا تمام می‌شود.
4. `npm run build` کد خروج ۰ می‌دهد.
5. حجم `dist/` حدود ۱٫۸ مگابایت است و فایل اصلی `App-*.js` ساخته شده.
6. `npm run dev` بالا می‌آید و `/dashboard` دادهٔ نمونه را نشان می‌دهد.
7. `/login` با لوگو و کارت ورود باز می‌شود (ورود واقعی انجام نمی‌شود).
8. `/harness` باز می‌شود و تب «انتقال» فهرست آزمون‌ها را نشان می‌دهد.
9. `npm run lint` فقط همان دو خطای شناخته‌شدهٔ `src/pages/Builder.jsx` و `src/pages/Convert.jsx` را می‌دهد.
10. در کنسول مرورگر، خطای شبکهٔ مربوط به `base44` دیده می‌شود؛ این خطا **مورد انتظار** است تا زمانی که بخش ۷ انجام شود.

اگر مورد ۱ یا ۴ شکست خورد، به‌احتمال زیاد `reference/` کپی نشده یا مسیر آن تغییر کرده است.

## ۷. آنچه این بسته تضمین نمی‌کند

این بسته انتقال **فایل** را تضمین می‌کند، نه استقلال **سرویس**. سه وابستگی باقی‌ماندهٔ ریشه:

| # | نقطه | فایل | اثر اگر Base44 نباشد |
| --- | --- | --- | --- |
| ۱ | Provider احراز هویت ریشه | `src/lib/AuthContext.jsx` (در `src/App.jsx`) | در هر بارگذاری خطای شبکه در کنسول |
| ۲ | صفحهٔ ۴۰۴ | `src/lib/PageNotFound.jsx` | فراخوانی `auth.me` روی مسیر ناشناس |
| ۳ | پلاگین ساخت | `vite.config.js` (`base44()`) | تزریق تنظیمات پلتفرم در ساخت |

موتور حسابداری (`src/a1`، `src/core`، `src/adapters`) هیچ واردات اجرایی از Base44 ندارد؛ تنها ارجاع، یک
توضیح در `src/a1/lib/v21Posting.js` است. یعنی **داده و محاسبه مستقل‌اند؛ تنها ریشه وابسته است.**
ترتیب برداشتن این سه نقطه و سپس ورود و دیتابیس واقعی در `docs/POST-TRANSFER-RUNBOOK.md` آمده است.
