# گزارش یکپارچه‌سازی پنل صراف (سه پوسته + محیط آزمون)

دامنه: میزکار دسکتاپ (`/dashboard`)، پوستهٔ موبایل (`/mobile`)، محیط آزمون (`/harness`) و رجیستری مرکزی `src/core/registry/modules.js`.

این سند نتیجهٔ آخرین بازبینی ساختاری و آزمون‌های خودکار است؛ هیچ داده یا منطق مالی در آن تغییر نکرده و همهٔ اعداد از اجرای همان لحظهٔ آزمون‌ها گرفته شده‌اند.

## روش بررسی

| لایه | چه چیزی بررسی شد |
|---|---|
| رجیستری | یکتایی شناسه، نام فارسی، گروه ناوبری، بخش مجوز، آیکون و مقصد |
| میزکار | فهرست ماژول‌ها، میان‌برهای لپ‌تاپ، منوها، برگهٔ «همه امکانات» |
| موبایل | تب‌ها، تایل‌های میزکار، منوی «بیشتر»، دسترسی نقش کارمند |
| محیط آزمون | نگاشت سناریوها به بخش‌های مرجع، فهرست، جزئیات و دفاتر |
| قرارداد درگاه | ۱۳ عملیات درگاه برای حافظه، موتور محلی و آداپتر لپ‌تاپ |

## تفاوت‌هایی که پیدا شد و اصلاح شد

| # | تفاوت | اصلاح |
|---|---|---|
| ۱ | فهرست ماژول‌های سه محیط جداگانه تعریف شده بود | همهٔ محیط‌ها از `CORE_MODULES` و `CENTERS` می‌خوانند |
| ۲ | آیکون هر بخش در چند فایل تکرار شده بود | یک منبع: `moduleIcons.js` با آیکون مرجع برای ۲۵ بخش و مرکز معاملات |
| ۳ | میان‌برهای میزکار با شناسه‌های قدیمی کار می‌کردند | `laptopHomeConfig.js` روی شناسه‌های مرجع بازنویسی شد |
| ۴ | «مرکز معاملات» در ناوبری موبایل نبود | در تب عملیات و منوی بیشتر اضافه شد (فقط‌خواندنی و جدا از مفاد معاملات) |
| ۵ | نام جایگزین `remittances` / `ledgers` به بخش اشتباه می‌رفت | `MODULE_ALIASES` و `canonicalId` در رجیستری |
| ۶ | آداپتر موبایل نقش و مجوزها را از نشست نمی‌خواند | همان `data.role` و `data.permissions` موتور مشترک استفاده می‌شود |
| ۷ | سناریوهای محیط آزمون با شناسه‌های محلی کار می‌کردند | نگاشت ۹ سناریو به بخش مرجع با `canonicalId` |
| ۸ | شماره‌گذاری ارجاعی ۱ تا ۲۵ در منو، سرصفحه، تایل‌ها و دکمه‌ها | به‌طور کامل حذف شد؛ شماره‌گذاری اسناد حسابداری دست‌نخورده است |
| ۹ | ستون وضعیت برای نقش‌های صراف و نماینده نمایش داده می‌شد | ستون‌های وضعیت برای این نقش‌ها پنهان شد |

## نتیجهٔ آزمون‌ها (اجرا شده)

- **ممیزی سرتاسری پنل:** ۷۷ از ۷۷ موفق، بدون خطا.
- **ماتریس آمادگی انتقال:** ۱۰۲ مورد — ۹۸ PASS، ۰ FAIL، ۴ BLOCKED.

| دسته | وضعیت |
|---|---|
| ساختار ۲۵ بخش | PASS |
| موتور داده و ذخیره‌سازی | PASS |
| دفاتر اختصاصی حساب‌ها | PASS |
| مجوزها و گیت نقش | PASS |
| گزارش‌ها و عملیات | BLOCKED (انتخاب سیاست سه گزارش) |
| عملیات، اسناد و ابطال | PASS |
| مرکز معاملات و مفاد معاملات | PASS |
| چیدمان موبایل و لپ‌تاپ | BLOCKED (اجرای واقعی مرورگری) |
| بخش‌های سازمانی | BLOCKED (اتصال دادهٔ واقعی) |
| احراز هویت و انتقال | BLOCKED (ورود واقعی کاربران) |

## موارد باز (خارج از دسترس این محیط)

۱. انتخاب سیاست ارز، نرخ و طبقه‌بندی برای سه گزارش مالی تا از BLOCKED خارج شوند.
۲. اتصال پایگاه داده واقعی برای ماژول‌های سازمانی.
۳. آزمون مرورگری روی دستگاه واقعی (کلیک، چاپ، هم‌پوشانی پیکسلی).
۴. جایگزینی نقش‌های شبیه‌سازی‌شده با احراز هویت واقعی.

## وضعیت بیلد

بیلد پروژه بدون خطا و بدون هشدار وابستگی انجام می‌شود و همهٔ مسیرهای هر سه محیط از همان رجیستری مرکزی ساخته می‌شوند.
