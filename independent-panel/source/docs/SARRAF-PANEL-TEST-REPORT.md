# گزارش آزمون پنل صراف — دادهٔ محلی

نوع سند: گزارش آزمون (خودکار + دستی)
دامنه: ۲۵ بخش پنل، در دو پوستهٔ موبایل (< ۷۶۸px) و لپ‌تاپ (≥ ۷۶۸px)
داده: کاملاً ساختگی و درون‌حافظه‌ای؛ هیچ اتصالی به دیتابیس، Supabase، IndexedDB، localStorage یا سرویس بیرونی وجود ندارد.
وضعیت ساخت: build بدون خطا؛ قرارداد درگاه داده ۱۵/۱۵؛ کنترل رجیستری ۶۰ مورد بدون خطا.

## ۱. روش آزمون

**الف) آزمون خودکار درون‌برنامه‌ای**
مسیر: «گزارش خطاها و فیلدها» ← دکمهٔ «اجرای ممیزی» (هر دو پوسته).
پیاده‌سازی: `src/core/audit/panelAudit.js` روی درگاه حافظه‌ای تازه؛ هر بررسی درگاه مستقل می‌سازد تا آزمون‌ها روی هم اثر نگذارند.
اجرای خط فرمانی برای CI/بازبینی: `npx esbuild src/core/audit/nodeRunner.js --bundle --format=esm --platform=node --alias:@=./src --outfile=/tmp/audit.mjs && node /tmp/audit.mjs`

**ب) آزمون دستی (گردش عملیات)**
رهگیری گام‌به‌گام کد مسیر کاربر در هر دو پوسته: ورود → انتخاب بخش → فهرست/جستجو/فیلتر → فرم → ثبت → مشاهدهٔ اثر در دفتر کل، گزارش، مانده و سوابق → ویرایش → ابطال → قفل شدن سند → مجوزها.
اجرای واقعی کلیک‌ها در مرورگر به Testing Agent سپرده می‌شود (سناریوها در بخش ۶).

| ورود و انتخاب بخش از خانه/تب/منو | موفق | همهٔ کاشی‌ها، ردیف‌ها و منوها به `openModule` یا `handleAction` وصل‌اند؛ آرگومان بدون مقصد وجود ندارد |

| ثبت حوالهٔ ارسالی/دریافتی با تسویهٔ واسط و فوری | موفق | واسط: بدهی در حساب حواله در جریان؛ فوری: اثر روی صندوق/بانک |
| ثبت خرید/فروش/تبدیل اسعار | موفق | دو سطر ارزی، کمیشن درآمدی، ماندهٔ دو صندوق |
| ثبت سند روزنامچهٔ ساده و چندسطری | موفق | رد سند ناتراز، پذیرش سند تراز، شمارهٔ یکتا |
| دخل/خرج صندوق با طرف حساب مشتری/نمایندگی/سایر | موفق | سطر دفتر با طرف حساب و ماندهٔ درست |
| ویرایش سند از فهرست بخش | موفق | سند و همهٔ مشتقات هم‌زمان به‌روز می‌شوند؛ شمارهٔ سند حفظ می‌شود |
| ویرایش سطر دفتر کل از سند اصلی | موفق | باز شدن فرم صحیح سند؛ سطر دفتر مستقل قابل ویرایش نیست |

| رد ابطال دوباره و رد ابطال سند معکوس | موفق | پیام روشن، بدون تغییر داده |
| غیرفعال‌سازی مشتری/نمایندگی/صندوق/بانک/ارز/حساب | موفق | وضعیت «غیرفعال»، سوابق و مانده‌ها دست‌نخورده |

| پیوند دو پوسته | موفق | رجیستری واحد برای ۲۵ بخش، فیلد فرم‌ها و آیکون‌ها |

## ۴. ایرادهایی که در جریان آزمون پیدا و اصلاح شد

1. ذخیرهٔ فرم بدون انتظار برای نوشتن؛ اعلان موفق پیش از ثبت و امکان ثبت تکراری → ذخیرهٔ async با قفل دکمه.
2. نبود شمارهٔ یکتا برای اسناد → شماره‌گذاری JE/TR/EX/EXP/CF.
3. دفتر کل و گزارش عملیات دستی و دارای ردیف‌های بی‌مرجع → مشتق از اسناد با `documentId`.
4. به‌روز نشدن دفتر و گزارش پس از ویرایش/حذف سند → بازسازی مشتق در هر تغییر.
5. امکان ویرایش مستقیم سطر دفتر کل → فقط‌خواندنی.
6. بی‌اثر بودن سند معکوس در دفتر → سطرهای معکوس و صفر شدن جمع سند.
7. نبود اعتبارسنجی تکرار و ارتباط → افزودن قواعد نام/کد یکتا، ارز صندوق، طرف حساب، حساب مصرف.
8. نمایش `convert/buy/sell` در فرم لپ‌تاپ → فارسی‌سازی نوع معامله.
9. ثبت گردش صندوق با وضعیت «موقت» → «قطعی».
10. باز شدن فرم خالی در «ویرایش از سند اصلی» برای گردش صندوق → نگاشت `cashFlowDraft`.
11. نادیده گرفتن اسناد مصرف و اسعار در موجودی صندوق → مانده از دفتر کل.
12. گردش تکراری پرداخت کرایه هم‌زمان با سند مصرف → حذف رکورد تکراری.
13. کارت «مفاد معاملات» همیشه «محاسبه نشده» → مقدار واقعی از سطرهای درآمد/مصرف دفتر.

## ۶. سناریوهای آمادهٔ Testing Agent

1. «ثبت یک مصرف نقدی از صندوق افغانی و بررسی کاهش موجودی صندوق، سطر دفتر کل، گزارش عملیات و مفاد و زیان.»
2. «ابطال یک حوالهٔ ارسالی با علت و بررسی ثبت سند معکوس، صفر شدن اثر در دفتر کل و قفل شدن ویرایش سند اصلی.»
3. «ورود با نقش کارمند و بررسی پنهان بودن بانک، روزنامچه و دفتر کل و غیرفعال بودن دکمه‌های ثبت.»
4. «ویرایش سطر دفتر کل از سند اصلی و بررسی به‌روز شدن گزارش و مانده صندوق.»
5. «اجرای ممیزی از بخش گزارش خطاها در موبایل و کنترل موفق بودن همهٔ گروه‌ها.»
